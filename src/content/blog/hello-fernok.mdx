有一个下午，我打开收藏夹，发现里面躺着十几个「以后要看」的链接。它们有一个共同点：我完全不记得当初为什么要收藏。

这大概是我想要一个个人站点的最直接原因。不是为了拥有一个更漂亮的简历，也不是因为「每个开发者都该有博客」这种说法，而是想给那些真正想明白的东西，找一个不会被信息流冲走的地方。

## 为什么要有一个自己的地方

社交平台擅长传播，不擅长保存。你写了一段很长的思考，它会被切成卡片、被算法排序、被下一条内容覆盖。半年后你想回头找，只能靠模糊的记忆和关键词搜索。

个人站点不一样。它慢，但它有一个确定的地址。你可以把它当成一个公开的笔记本，也可以把它当成一个长期项目。最重要的是，**它完全属于你**。

我给自己定了三个很简单的目标：

- 写清楚一件事，而不是写满一页；
- 每个项目都能被打开、被使用；
- 让内容比样式活得更久。

## 这次想做得不一样

以前我也搭过博客。通常的流程是：选一个主题，改两天 CSS，写一篇文章，然后就没有然后了。

这次我想把「维护成本」降到接近零：

<Steps>
  <Step>
    **内容就是文件。** 文章、文档、项目介绍都放在 `src/content`，用 Markdown 或 MDX 写。新增一篇文章只需要新建一个文件。
  </Step>
  <Step>
    **构建交给自动化。** 推到 `main`，GitHub Actions 用 Bun 安装依赖、构建、部署。没有手动上传，也没有「忘了 build」。
  </Step>
  <Step>
    **评论不自己造轮子。** Giscus 把评论存进 GitHub Discussions，登录、通知、审核都复用 GitHub。
  </Step>
</Steps>

## 技术选择

这个站点最终用了这些：

| 层 | 选择 | 原因 |
| --- | --- | --- |
| 框架 | Astro 7 | 内容优先，默认零客户端 JS |
| 内容 | Markdown / MDX | 可读、可版本控制、可迁移 |
| 运行时 | Bun | 安装快，脚本简单 |
| 部署 | GitHub Pages | 免费、稳定、和仓库天然集成 |
| 评论 | Giscus | 数据留在 GitHub，不需要数据库 |

Astro 的内容集合会在构建时校验 frontmatter。如果日期格式写错了，或者漏了必填字段，构建会直接失败，而不是等到线上才发现。

<Callout type="info" title="关于零 JS">
  这个站点只在必要的地方加载 JavaScript：搜索、筛选、复制代码和评论。页面本身是静态 HTML，禁用它也能正常阅读。
</Callout>

## 视觉为什么长这样

我很喜欢 [NVIDIA Build](https://build.nvidia.com/models) 的模型目录：深色背景、细边框、几乎不使用装饰，信息密度很高，但并不拥挤。

所以这次没有做花哨的插画，而是把精力放在排版、留白和状态表达上。绿色只出现在真正需要被注意的地方：当前导航、可交互元素、状态点。其余的部分尽量安静。

接下来会先补齐三件事：

1. 把 `trendshift-lite` 的构建过程写成一篇完整的复盘；
2. 给文档补上搜索与版本说明；

如果你也在犹豫要不要搭自己的站点，我的建议是：先写第一篇文章，再选框架。内容会告诉你需要什么。
