这个仓库叫 `fernok.github.io`，属于 GitHub Pages 的用户站点，因此部署后直接使用根域名 `https://fernok.github.io`，不需要配置 `base`。

## 仓库设置

1. 进入 `Settings → Pages`；
2. 在 `Build and deployment` 下把 `Source` 设为 **GitHub Actions**；
3. 不需要选择分支，也不需要 `gh-pages` 分支。

工作流会在每次推送到 `main` 时运行。

## 工作流

完整文件在 `.github/workflows/deploy.yml`：

```yaml
name: Deploy to GitHub Pages

on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: false

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: oven-sh/setup-bun@v2
        with:
          bun-version: 1.4.4
      - run: bun install --frozen-lockfile
      - run: bun run build
        env:
          PUBLIC_GISCUS_REPO_ID: ${{ vars.PUBLIC_GISCUS_REPO_ID }}
          PUBLIC_GISCUS_CATEGORY_ID: ${{ vars.PUBLIC_GISCUS_CATEGORY_ID }}
      - uses: actions/configure-pages@v5
      - uses: actions/upload-pages-artifact@v3
        with:
          path: dist

  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - id: deployment
        uses: actions/deploy-pages@v4
```

## 关键点

- **`bun install --frozen-lockfile`**：CI 必须使用提交过的 `bun.lock`，避免依赖漂移。
- **`site` 配置**：`astro.config.mjs` 中的 `site: 'https://fernok.github.io'` 用于生成 canonical、RSS 和 sitemap。
- **`permissions`**：缺少 `pages: write` 和 `id-token: write` 时，部署会失败。
- **`.nojekyll`**：`public/.nojekyll` 防止 GitHub Pages 忽略 `_astro` 目录。
- **Giscus 变量**：通过仓库 Variables 注入，避免把 ID 硬编码在多个地方。

<Callout type="warn" title="不要在仓库设置里选分支">
  如果 `Source` 仍然指向 `gh-pages` 分支，Actions 构建的产物不会被发布。改成 **GitHub Actions** 后重新运行工作流。
</Callout>

## 手动部署

如果只是想临时发布一次，也可以在本地构建后手动推送：

```bash
bun run build
bunx astro preview
```

或者使用 `gh` 触发工作流：

```bash
gh workflow run "Deploy to GitHub Pages"
gh run watch
```

## 自定义域名

1. 在仓库 `Settings → Pages → Custom domain` 填入域名；
2. 在 `public/CNAME` 写入同样的域名（否则每次部署会被清空）；
3. 在 DNS 添加 `CNAME` 记录指向 `fernok.github.io`；
4. 等待 GitHub 签发 HTTPS 证书。

如果使用子路径（例如 `username.github.io/blog`），需要把 `astro.config.mjs` 的 `base` 改成 `'/blog'`，并同步所有内部链接。这个站点是用户主页，不需要这一步。

## 排障

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 404 / 样式丢失 | `base` 配置错误或 `_astro` 被忽略 | 检查 `.nojekyll` 与资源路径 |
| 工作流成功但页面没更新 | Pages Source 选错 | 改为 GitHub Actions |
| 评论不加载 | 变量未注入或 App 未安装 | 查看构建日志与仓库安装 |
| 构建失败 | lockfile 不同步 | 本地 `bun install` 后提交新的 `bun.lock` |

## 发布之后

部署成功并不代表结束。建议每次上线后做三件事：

1. 用手机打开首页和一篇长文；
2. 检查 RSS 和 sitemap 是否可访问；
3. 在文章下留一条测试评论，确认 Giscus 工作正常。
